Where are a token's most similar tokens?

Each token (a word or piece of a word) in a text is coloured by where its 64 most similar tokens sit: in another text, in the same text more than 64 tokens away, or in the same text within 64 tokens. Similarity compares two tokens' current states and, with memory, their recent pasts; a memory knob sets how far back the comparison looks. Click any token to inspect its neighbours as text and check the colour yourself.

Text and position

32 texts—the first 2,047 tokens of each document—plus 4 spliced texts. The first 255 tokens of each text are shown in grey: they are part of later tokens' histories, but are never selected as queries or neighbours.

Model and layer

Two models (16 blocks, width 2,048 each) read the exact same tokens. Layer chooses which block's output state is compared: after block 4, 8, 12, or 16 (layer 16 is taken before the final normalisation).

Memory: comparing two pasts end to end

Two tokens are compared by lining up their histories at the right end and comparing them step by step going back, with older steps counting less. Memory sets how far back the comparison looks: none (current token only), about 2, about 8, about 64 tokens, or the whole past equally weighted. Each token's state first has one average removed and is scaled to length 1, so comparison is by angle (cosine). Because each step pairs matching lags rather than averaging each past, two neighbouring tokens are not similar just because their pasts overlap. Two effects follow: a match carries over to the next token along the text, so neighbours appear in runs; and at the whole past, unequal history lengths push tokens toward similar positions even in random text.

Settings: what is subtracted, what is barred

One average removed subtracts the average hidden state across all texts (one average per model and layer). Each text's own average removed (offered with nearby tokens barred) subtracts that document's whole average—including later tokens; it can also remove topic-related differences. Nearby tokens barred forbids neighbours within 64 tokens in the same text, so orange vanishes by rule rather than as a finding.

If several tokens tie at the 64th distance, the list fills remaining slots in text-and-position order and marks them ≈. A dot is a token

One dot is one token: one position in one text (a word or a piece of a word, as the model splits text). Hover over a dot (tap on a phone) to read the token with the 8 tokens before and after it and the text it comes from. A token keeps its dot at every layer, so the slider moves dots, it never swaps them.

Layer: the slider and Play

Each model reads a token through 17 layers, numbered 0 to 16: layer 0 is the token's input vector and layer l the output of block l of 16. The slider picks the layer; ← and → step one layer; Play runs from 0 to 16. Between two layers dots are drawn part of the way along a straight line, for the eye only: nothing was computed in between. The bars above the slider show how much of the two plotted modes sits at each layer.

The two axes are two modes

The embedding gives every token 64 coordinates at every layer, called modes and numbered k = 1, 2, …; this page carries the first 16. A mode is one pattern over all (token, layer) pairs at once, computed from which tokens lie close to which: at each layer two tokens are linked if either is among the other's 15 nearest by the angle between their activation vectors, ties included (so a token can have far more than 15 links), and each token is tied to itself at the next layer. Mode 1 is the smoothest pattern (it changes least between linked tokens and between neighbouring layers), and each later mode is a little less smooth. Because a mode spans every layer, its value at layer 5 and at layer 6 are the same coordinate, which is what lets a dot move continuously. Choose the two plotted modes under Axes. The sign of a mode is arbitrary (flipping it mirrors the plot). Each axis is scaled to its own mode and kept the same at every layer; a few far-out tokens are drawn on the frame's edge and counted (see Axis limits).

Coupling strength

How strongly each layer is tied to the next. t* is the strength at which the first pattern that varies only along depth (the same for every token) and the first pattern that varies across tokens get the same smoothness score: a crossing point, not a best value. t*/16 is a sixteenth of it, a much looser tie under which a mode can change more from layer to layer. t* is found separately for each model and set; its value is in each plot's caption.

What do a language model's similar tokens have in common?

The long-term goal of this project is a map of what a language model does to a text, layer by layer. The plan is to connect the positions of tokens (a token is a word or piece of a word) whose internal states are similar, then find the main patterns of that graph. Whether such a map is useful depends on what "similar" ends up meaning. We wanted similarity to include each token's recent past, a setting we call memory. A small pilot suggested a catch: memory might simply make every token resemble its neighbours in the same text. The map would then say little more than "where am I in which document". Stage A (this site) checks that worry. It measures neighbours, graph weights and prediction agreement; it does not build the map. Stage B, the later stage that would build the map, is designed but not run. Decisions about the plan were made by the project's owner, Charles R-W.

We ran two 1-billion-parameter language models, Pythia-1b and OLMo-1B. Their tokenizers split these texts into identical tokens. Each model read the first 2,047 tokens of 32 long documents from the Pile test set. The documents come from 10 sources, at most four per source. We analysed each token's hidden state after every second block (2, 4, …, 16). The main results use the state after block 8 of 16 ("layer 8"). Nothing was trained.

How we counted neighbours

  1. Prepare each token's vector. At a chosen layer, subtract one average hidden state, taken over all 32 texts, so that what every token shares does not swamp the comparison. Then scale each vector to length 1, so loud and quiet tokens count equally (comparison by angle, or cosine).
  2. Compare two pasts end to end. To compare token t with token t′, line up their histories at the right end: t with t′, t−1 with t′−1, and so on going back. Add the step-by-step similarities, with weights that fade by a fixed factor per step. Memory sets how fast they fade, that is, how far back the comparison looks: none, about 2, about 8, about 64 tokens, or the whole past equally weighted. Then divide by the size of each weighted past, so the result is the cosine between the two weighted pasts. With no memory, only the two current vectors are compared; each already reflects earlier text, through attention. Because each step pairs matching lags, a token is never compared with its own position, so tokens t and t+1 are not similar just because their pasts overlap.
  3. Take the 64 most similar tokens. The first 255 tokens of each text are part of later tokens' histories, but are never selected as queries or neighbours. For each of the 57,344 remaining tokens, find the 64 most similar among all the others: from any text, earlier or later in the passage.
  4. Sort the 64 by where they sit. Each neighbour is in another text, in the same text more than 64 tokens away, or in the same text within 64 tokens (before or after). Average those shares over all analysed tokens. If the 64 were drawn at random, 97% would sit in other texts.

Three findings

Memory pulls neighbours into the same text, and right next door. Even with no memory, most of a token's 64 nearest tokens sit in its own text: 59% in Pythia-1b and 62% in OLMo-1B at layer 8, where chance would put 97% in other texts. Memory moves them right next door: in Pythia-1b the share within 64 tokens goes from 13% with no memory to 51% at memory 64. Now give each token a fixed random vector instead and run the same comparison. At memory 64 those vectors still keep 54% of neighbours in the same text, because texts reuse their vocabulary. But they put only 9% within 64 tokens, against the model's 51%. At the whole past, random vectors already put 34% within 64 tokens. E1: Where are a token's most similar tokens? →

Neighbours agree on what comes next, until memory grows. With no memory, a token's neighbours share its top next-token prediction about twice as often as stand-ins do: 22% versus 10% in Pythia-1b at layer 8 (OLMo-1B: 22% versus 11%). A stand-in is another occurrence of the neighbour's token in the neighbour's text, picked at random from tokens that are not neighbours. If neighbour and query share a text, the stand-in must also be in the same distance band from the query as the neighbour. The advantage shrinks as memory grows, to nearly nothing for the whole past. One limit: the comparison uses only pairs that found a stand-in, in groups where at least half the pairs (and at least 200) found one. That is 48% of all pairs with no memory, and 6% for the whole past. E2: Do similar tokens agree about what comes next? →

A rule written in advance picked a setup; the owner then redesigned Stage B. A rule written before any results existed was applied to 32 ways of building the similarity graph. It had four tests: enough of the graph's link weight goes to other texts; not too much goes to nearby tokens; memory changes the neighbours; and the neighbours differ from what the tokens alone give. It picked lengths kept (dot), memory 64, one average removed, nothing barred. The "dot" setting measures the distance between histories with vector lengths kept, so louder vectors count more. "Barred" tokens are not allowed as neighbours; "nothing barred" means every analysed token may be one. After seeing Stage A's findings, the owner set that pick aside. Stage B was redesigned around independent text chunks, one per document, compared by angle with nothing barred. The new Stage B is designed, not yet run. A second study: tokens through the layers

A separate study builds, for fixed samples of these texts, one space that holds all 17 layers of a model at once, so that the same token can be followed from the input to the last block. It asks what the main patterns of that space look like, how they change with the sample, whether the two models agree, and where tokens of another kind (random or shuffled) land. It uses no memory kernel and describes these fixed samples; it is not a test.

The two models give the same tokens similar spaces; much of the overlap survives scrambling which occurrence of each word piece is matched with which. On a set's own tokens, the two models' first 16 patterns overlap 0.62 to 0.72 (1 = the same space, 0 = nothing shared). Reordering the occurrences within each word piece in one model, which leaves some tokens matched, still gives 0.37 to 0.54 in the document sets; reordering all tokens freely gives at most 0.005. Why the whole past behaves differently

When every earlier token counts equally, two histories of different lengths can only be paired up to the shorter one. That length mismatch caps how similar an early token and a late token can ever be, no matter how alike their texts are. Neighbours therefore cluster at similar positions in the text. For each token we took the median distance to its same-text neighbours; at layer 8 in Pythia-1b those medians averaged 21 tokens. At the whole past, 34% of random-vector neighbours and 93% of Pythia-1b neighbours are within 64 tokens. So the comparison itself produces a pull towards similar positions, even without the model's states; the rest of the gap is not explained by this control.

Variations and supporting figures (8 notes, 9 figures)
  • Each text's own average removed: subtracts each document's average over all its tokens, including later ones, and can also remove topic-related differences along with offsets. With each text's own average removed, Pythia-1b's own-text share goes from 52% (no memory) to 88% (memory 64), against 59% → 98% with one average removed. Because this average includes later tokens, it is a retrospective contrast rather than a correction.
  • Nearby tokens barred: forbids same-text neighbours within 64 positions, so the nearby share is zero by rule rather than by discovery. At memory 64 in Pythia-1b, this rule removes, on average, 25% of the graph weight (defined in the table below) of queries from each text's last 512 tokens, and still leaves only 8% of the 64 nearest in other texts.
  • Own text barred: forces every neighbour into another text by rule, so it is shown only in the same-token comparison below rather than as a location share.
  • Lengths kept (the "dot" setting): ranks neighbours by the distance between the two weighted histories with vector lengths kept, so louder hidden states count more; at the whole past, tokens with the shortest histories end up close to everyone, moving most neighbours into other texts. The preference for short histories also appears with random vectors per token id, so it does not need the model's states.
  • Other layers: averaging across all 8 measured layers gives the same pattern—in Pythia-1b, own-text share rises from 63% to 97% at memory 64, with 47% within 64 tokens.
  • Spliced texts: two documents cut into alternating segments and analysed alone (with the 32 real texts' average removed). In Pythia-1b (mean of the 4 spliced texts, layer 8), same-source share beyond what position alone predicts drops from 18.6 percentage points with no memory to 4.8 at memory 64 and -0.1 at the whole past (OLMo-1B: -0.1). At the whole past, the average same-source share was within a percentage point of what the neighbours' position gaps predict.
  • Synthetic texts: artificial sequences with planted hidden states, slow drift, or pure noise, included as a visual reference rather than a test.
  • Overlap with text-only inputs: text-only inputs are vectors that know only which token is where: a fixed random vector per token id, or the model's input embeddings. At memory 64 in Pythia-1b (layer 8), 29% of neighbours are shared with whichever text-only input shares more, while only 15% remain from the model's own no-memory list.

Caveats

  • Shares are averages over tokens, not over pairs. Every analysed token counts once, so every text counts equally. The resampling intervals re-weight the 32 texts but do not recompute anyone's neighbours; they show how much texts differ, not what another corpus would give.
  • The sample is beginnings of long, mostly ASCII documents. At most four documents come from any single Pile source, and OLMo-1B's training data are not guaranteed to exclude these texts.
  • Values shown as 100% or 0% are rounded. At the whole past, own-text shares are more than 99% and other-text shares are under 1% in both models.
  • Text-only inputs have exact ties with no memory. Identical tokens sit at zero distance when memory is none, so ties at the 64th place are filled in text-and-position order (lowest text number first).
  • Barring rules fix shares by definition. Barring nearby tokens forces the within-64 share to zero, and barring the token's own text forces the other-text share to one; neither is a finding.

The pre-registered prediction advantage

Rather than looking only at the single top token, the measure fixed before the run (pre-registered) compares the two top-20 next-token lists, with their probabilities. For each pair, we sum the shared probability mass across tokens appearing in both top-20 lists and subtract the stand-in's shared mass. We average those differences within each group over its matched pairs, then give each group with enough stand-ins equal weight. At layer 8 with one average removed and no tokens barred, this prediction advantage falls from 0.121 with no memory to 0.003 for the whole past in Pythia-1b, and from 0.105 to 0.007 in OLMo-1B. Is the decline just a change in which groups enter the score?

No. Pairs are split into six groups by where the neighbour sits and whether its token is frequent (the neighbour's token occurs at least 20 times among the 57,344 analysed tokens) or rare (fewer than 20). Groups where fewer than half the pairs (or fewer than 200 pairs) find a stand-in are left out. Nearby groups never cleared that bar (0 of 40: two nearby groups at each of 4 layers and 5 memories), and rare-token groups often fell short too. At layer 8 in Pythia-1b with no memory, 13% of pairs found a stand-in in a left-out group and 38% found no stand-in at all. At memory 64, 15% found a stand-in but belonged to a group left out, and 46% found no stand-in.

What this does not show

  • Nothing causal. Whether the model uses these similarities was not tested.
  • What the stand-in does not control. It matches text, token, and distance band only; anything else a neighbour shares with the query, such as its recent past, counts toward the advantage by design.
  • Not that long-memory neighbours are "wrong." One plausible reading, not tested here: memory picks neighbours whose pasts resemble the query's (at memory 64 only 15% of a token's 64 neighbours are the same as with no memory; E1, layer 8), while the next-token prediction depends mostly on the current state.
  • The no-memory headline excludes rare-token and nearby groups. They did not have enough stand-ins.

The four tests

The tests look at the graph the old Stage B would have built. In that graph each late query spreads a total graph weight of 1 over all late candidates, more to the more similar ones. The spread is tuned to be about as concentrated as an even split over 64 tokens. At each layer a candidate passes if: (1) at least a quarter of the graph weight goes to other texts; (2) not too much goes to nearby tokens (at most 25% within 64 positions, or, when nearby tokens are barred, barring removes at most half); (3) memory changes the neighbours (at most half of the 64 nearest are the same as with no memory); and (4) at most half of the 64 nearest match those from either text-only input. Text-only inputs are vectors that know only which token is where: a fixed random vector per token id, or the model's input embeddings.

How the rule decided

The rule preferred candidates with no extra fixes (one average removed and nothing barred), then angle over lengths kept. No angle-based candidate passed without extra fixes. With angle comparison, memory 2 stayed too close to no memory; memory 8 passed on only 4 of Pythia-1b's 8 layers; and longer memories put too much graph weight within 64 tokens. With lengths kept, two candidates passed without extra fixes, at memories 8 and 64. Memory 64 won because its neighbours overlapped less with the text-only inputs. Its worst overlap (the largest with either text-only input, at any layer, in either model) was 25%, against 35% for memory 8.

Even that pick barely cleared the bar. It passed in Pythia-1b on exactly 5 of 8 layers, the minimum (and 7 in OLMo-1B). Its closest call was layer 10, where 24.95% of its graph weight sat within 64 tokens, against a limit of 25%. No second construction was added: there was no eligible passing alternative. The rule allowed one optional extra example, chosen by E2's prediction advantage. Why graph weight and the 64 nearest disagree

Graph weight does not go only to the 64 nearest tokens. In high-dimensional space, thousands of tokens are only moderately similar and sit at nearly equal distances. Each gets a sliver of weight, and together those slivers can outweigh the few close ones: about half or more of the weight ends up in other texts.

Averaged across all 8 measured layers for the rule's pick (M), 60% of graph weight in Pythia-1b lands in other texts (64% in OLMo-1B). On those exact same late queries and late candidates, only 36% of the 64 nearest tokens sit in other texts. For the same pick (lengths kept) over all 57,344 analysed tokens instead of the late pool, the share is 30%. Under angle comparison at the whole past, the split is even sharper: 50% of graph weight in Pythia-1b sits in other texts, versus 0.6% of the 64 nearest on the same queries.

Depth embedding of tokens

Tested: Pythia-1b and OLMo-1B, all 17 layers of each (layer 0 is the input; layer l is the output of block l of 16, one processing step of the model). The texts are the 32 Pile documents of the Viewer (the Pile is a public collection of text), named c00 to c31. 11 construction sets, each a fixed sample of 2,048 tokens (2,047 for a single text), built once per model: doc00, doc01, doc02 and doc04 (all of one document each), pairA (c00 and c01), pairB (c02 and c04), d04 (c00, c01, c02 and c04), d08 (c00 to c07), d16 (c00 to c15), d32 (c00 to c31) and rand (r0 to r3: sequences of random tokens whose word pieces were drawn uniformly, with replacement, from those that occur in the 32 texts; r4 is a further such sequence that no set uses). Three panels, fixed lists of token positions, are shown in every embedding: natural text (1,024 positions), random tokens (768) and shuffled texts (1,024; documents 0, 1, 2 and 4 with their tokens put in random order, s0 to s3). Main numbers: the first 16 modes, coupling strength t*.

What an embedding is here. A token is one word or piece of a word at one place in one text; the same word piece (for example " the") occurs as many tokens. At every layer the model computes a vector for each token (its activation). Two tokens of a set are linked at a layer if either one is among the other's 15 most similar tokens by angle, counting every token tied at the 15th place, so a frequent word piece can have hundreds of links at the input layer; all other pairs keep a tiny background weight. The links are then balanced so that every token's links add up to the same total, and each token is tied to itself at the next layer. A mode is one number for every token at every layer that averages zero over the tokens at each layer and changes as little as possible along the links and from layer to layer. Mode 1 is the smoothest such pattern, mode 2 the next, and so on (technically: eigenvectors of one Laplacian operator over all layers). The first few modes give every token a few coordinates at every layer, in one space shared by all layers. The coupling strength sets how tightly neighbouring layers are tied. Its main value, t*, is the strength at which the smoothest pattern that varies only with depth and the smoothest one that varies across tokens are equally smooth: a crossing point, not a best value. Nothing is trained. A token outside the set can be placed: at each layer it is linked to the set's tokens by the same rule, and its coordinates are solved over all layers together with the embedding held fixed, so its position at one layer also depends on its vectors at the other layers. Panel positions that are already in a set keep their own coordinates. The Depth embedding tab draws these spaces token by token.

How two spaces are compared. Most numbers below are an overlap between two embeddings on the same token positions: after subtracting each layer's average, do the first 16 coordinates in one embedding vary along the same directions, across those tokens, as the first 16 in the other? The overlap is 1 when they span the same space, however the axes are rotated, mirrored or scaled inside it, and 0 when they share no direction. Mode 3 of one embedding is never matched with mode 3 of another, and a high overlap does not mean equal distances or the same nearest neighbours. "All layers together" means the layers' rows are stacked into one comparison, not that 17 per-layer scores are averaged. These results describe these fixed samples; how much fresh samples would vary was not measured, and no number here is a test of a hypothesis.

Caveats

  • Near-tied modes. A cutoff at k modes is flagged when mode k and the next have smoothness scores (eigenvalues) within 1% of each other: such modes can mix under small changes in the data, so a cut between them may be arbitrary. The 1% line is the spec's display rule, not a proof. Of the 136 comparison records in the release (both strengths, all groups of tokens), 18 are flagged at 16 modes and 126 at 64. Flagged values are drawn open and left out of the ranges quoted for questions 2 and 3. The flags apply to the embeddings built over all layers; question 1's summaries include modes inside near-tied groups, and the layer-by-layer curves are not flagged.
  • Some per-layer overlaps are not defined. At t*, 18 of 918 per-layer values of the between-model overlap (in doc02 and pairB) are not reported, because at that layer, on those tokens, one model's first 16 coordinates do not give 16 independent directions (one is tiny next to the largest). At t*/16 it is 563 of 918, in all 11 sets; with the looser tie, modes tend to concentrate in fewer layers.
  • t* differs a lot between sets. It is computed for each set and model: from 4.33 to 20.7 in Pythia-1b and from 2.22 to 23.1 in OLMo-1B. The two lowest in each model are doc02 and pairB, the same two sets whose per-layer overlaps are undefined at t*. Sets are therefore compared at different absolute strengths.
  • The reordering references are not chance levels. A word piece that occurs once cannot move, and a random reordering leaves some tokens in place, so the word-piece reference mixes matched and reordered tokens; it is not an estimate of how much agreement the word piece causes. Where under 10% of a group can move, it says little (an open diamond in the figures).
  • One sample of each set, two models, 32 texts. There are no error bars across samples: lines in the figures span modes or reorderings. The texts are the beginnings of long Pile documents, as in Stage A.
  • Not done. No memory kernel: tokens are compared by their activations at each layer, with no extra comparison of their pasts as in Stage A (the activations themselves reflect earlier text). Method

Two language models read the same 32 texts once, and every hidden state is stored. For each token we ask where its most similar tokens are, when similarity compares two tokens' recent pasts. Stage A (this site) counts where those similar tokens sit and checks whether they share the model's next-token predictions. Stage B has since been redesigned around independent chunks of text, one per document; it is written up and reviewed, but nothing of it has been run.

Why measure neighbours first

The long-term aim is a map of what a language model does to a text, layer by layer. Each token is a point. Two points are linked when the model's hidden states there are similar, and the map is the main patterns of that graph. The owner asked that similarity should include each token's recent past, not only its current state. Here that is called memory: how far back the comparison looks, with older positions counting less. A free pilot on a small model (pythia-160m) found that with memory, a token's nearest neighbours moved into its own text and closer to it. The median distance to same-text neighbours (one average removed, range over the pilot's three layers) was 168–204 positions with no memory, 110–159 at memory 8, 26–60 at memory 64 and 16–17 at the whole past. A map built on such links might say little more than where in which text a token sits. So Stage A builds no map. It measures where neighbours are, and whether they share the model's next-token predictions, on two larger models and texts from the Pile.

The pilot used four Wikipedia articles, two Python standard-library files and two licence texts, 1,023 tokens each. It looked at layers 3, 6 and 9, and at each token's 64 nearest neighbours from position 128 on. Whether a map built on such neighbours would be mostly about position within each text was not measured.

Memory 2 was added between none and 8 to fill the gap, not because of any finding.

Models and extraction

Nothing is trained. Two models of about a billion parameters, Pythia-1b and OLMo-1B, each read every text once. Their tokenizers give identical ids on every accepted text, and the run stops if they do not; only their end-of-text ids differ. From that one pass we keep, at every position, the hidden state after each of the 16 blocks and the model's 20 most likely next tokens. The analysis uses the states after blocks 2, 4, ..., 16. Texts and tokens

Each text is the first 2,047 tokens of a long, mostly ASCII document from the Pile's test split. There are 32 texts from 10 Pile sources, at most four from each. Before each text, the model reads its own end-of-text token at position 0; that position is left out of every average and every comparison. The first 255 text tokens are part of later tokens' histories, but are never selected as queries or neighbours. That leaves 57,344 analysed tokens, from position 256 to the end of each text. Fixed samples of them are the queries for the prediction check, the graph-weight test and the audit.

The texts are a capped sample of the beginnings of long, mostly ASCII Pile test documents. A document in the Pile's test file was eligible if it contains no special or placeholder strings, is at least 95% ASCII and is at least 2,048 tokens long. The eligible documents were shuffled with a fixed seed and taken in that order, keeping the first 2,047 tokens of each. A document was skipped if more than 30% of those tokens are whitespace only, if more than 10% of its 32-token passages repeat an earlier one, if it shares a 32-token passage with an accepted text, or if its source already has four accepted texts. 32 texts from 10 sources were accepted. Similarity

Every result here depends on how the similarity of two tokens is defined. Four choices set it: how far back into each token's past the comparison reaches (memory); whether vectors are compared by angle (cosine) or by the distance between histories with vector lengths kept (the "dot" setting); which average is removed, and whether some tokens are barred as neighbours; and how exact ties are broken. The same comparison is also run on text-only inputs, vectors that know only which token is where, to show what the token sequence and the formula give by themselves.

Memory: two pasts lined up at their ends

To compare token $t$ with token $t'$, line up their pasts so that the two tokens sit at the right-hand end. Compare $t$ with $t'$, then $t-1$ with $t'-1$, then $t-2$ with $t'-2$, and so on, and add up these step similarities with weights that fade going back. Memory $m$ sets how fast they fade: roughly, the last $m$ tokens count. "None" compares only the two current states, each of which already reflects earlier text through attention. "Whole" weights every earlier position equally. Each step pairs two positions the same distance apart, so two adjacent tokens are not similar merely because their pasts overlap.

With $y_u$ the hidden state at position $u$ after the average is removed (and, when comparing by angle, scaled to unit length; $y_u = 0$ before position 1), the similarity of tokens $t$ and $t'$ is:

$$K_a(t,t') = \sum_{s \ge 0} a^s\, \langle y_{t-s},\, y_{t'-s} \rangle = \langle y_t, y_{t'} \rangle + a\, K_a(t-1,\, t'-1).$$

Memory $m$ sets $a = 1 - 1/m$: none ($a = 0$, the current token only), 2 ($a = 0.5$), 8 ($0.875$), 64 ($0.984375$) and the whole past ($a = 1$). Compared by angle (cosine), the viewer's setting, the vectors are normalised twice: each token's vector to unit length before the sum, so every token counts equally, and then the weighted past, $d = 1 - K_a(t,t')/\sqrt{K_a(t,t)K_a(t',t')}$. With lengths kept (the "dot" setting), louder vectors count more, and the distance is half the squared distance between the two weighted histories, scaled: $\big[(K_a(t,t) + K_a(t',t'))/2 - K_a(t,t')\big]/\bar K$, with $\bar K$ the mean of $K_a(t,t)$ over the analysed tokens. Three properties matter when reading results. Neighbours come in runs: $K(t,t')$ and $K(t+1,t'+1)$ share all but one term, so a chance agreement between two pasts persists along the alignment. At the whole past, pasts of different lengths are compared only over the shorter one: compared by angle, tokens at positions $t < t'$ can be at most $\sqrt{t/t'}$ similar, so neighbours sit at similar positions even for text with no structure; with lengths kept, the earliest analysed tokens end up close to everyone. And the recursion is computed exactly, in float64, never through a closed form that overflows.

What is removed, and which tokens are barred

Before comparing, an average hidden state is removed, so that what every token shares does not swamp the comparison. The main setting removes one average, taken over all 32 texts, and lets every other analysed token be a neighbour. Two kinds of contrast are also run: removing each text's own average instead, and barring either nearby tokens (same text, within 64 positions) or the token's whole own text. These contrasts are not corrections. A bar sets the barred share to zero by rule, so it says nothing about the model there.

Text-only inputs

To separate what the model computes from what repeated tokens and the comparison formula give on their own, the same pipeline is run on two inputs that know only which token is where. One gives each token id a fixed random vector. The other is each model's input embedding (layer 0), before any block runs. Where a model's neighbours match these, the pattern could have come from the text alone.

The random vectors are Gaussian, width 2,048, drawn once with a fixed seed, and the same at every position and in both models; they have no layers. Neither model adds a position embedding at the input, so layer 0 also depends only on the token id. Both inputs go through the same averaging, scaling and memory sum as the hidden states.

Ties

Real model states almost never tie. The text-only inputs do: with no memory, two copies of the same token are at distance exactly zero, so a frequent token can have hundreds of tied candidates.

Two candidates are tied if their distances differ by at most one part in $10^{12}$. The 64 neighbours are every candidate strictly closer than the 64th distance, plus tied candidates at the cutoff taken in (text, position) order, lowest text first. For the text-only inputs with no memory, this order partly reflects how the texts are numbered; the size of that effect was not measured. Overlaps between two neighbour lists are computed as the expected overlap under random tie-breaking, $\mathbb{E}|A \cap B| = \sum_j P(j \in A)\, P(j \in B)$. The rule for Stage B (below) instead uses the largest overlap the ties allow, so a candidate cannot pass by tie-breaking.

What was measured

Stage A computes no graph patterns. It makes four measurements on the stored hidden states. First, for every analysed token and every setting, its 64 nearest neighbours and where they sit: in another text, in the same text more than 64 positions away, or within 64 positions. Second, for sampled tokens near the end of each text, how the weight of the graph a later stage would have used is spread over those same three places. Third, on a fixed sample of tokens, whether neighbours share more of the model's next-token prediction than stand-ins do. Fourth, a rule written before any results, which used the graph weights and neighbour lists on those late tokens to choose a setting for Stage B. The owner later set its pick aside.

Every analysed token, every setting (2 models × 2 ways of comparing × 2 averages × 5 memories × 3 bar rules × 8 layers, plus the 2 text-only inputs): the shares of its 64 neighbours in other texts, in the same text more than 64 positions away, and within 64 positions on either side, each averaged over tokens; each token's median position gap to its same-text neighbours, averaged over tokens; the share whose current token is the same as the query's; and the overlap with the text-only inputs' lists and with the same setting's list at no memory. Chance levels are the shares among the tokens allowed as neighbours. (E1)

Graph weight on the last 512 positions. In the graph the original Stage B would have built, each token spreads a total weight of 1 over all other tokens, more to closer ones: $q(j \mid i) \propto \exp(-\beta_i (d_{ij} - \min_j d_{ij}))$, with $\beta_i$ set so that $1/\sum_j q(j \mid i)^2 = 64$. That is as concentrated as an even split over 64 tokens, yet much of the weight can still sit in a long, thin tail. For the sampled queries in the last 512 positions, against every token in the last 512 positions of every text, we record the weight on each of the three places; with nearby tokens barred, also the weight the unbarred row had put on them. Nothing $N \times N$ is stored and no eigenproblem is solved. (E3)

The prediction check on the query sample, with neighbours from layers 4, 8, 12 and 16. For a query and one of its neighbours, the prediction overlap is the probability both positions give to the same next tokens, within their top-20 lists. It is compared with the same overlap for a stand-in: another occurrence of the neighbour's token in the neighbour's text, not on the query's neighbour list, chosen at random. If the neighbour is in the query's text, the stand-in must also be at a similar distance from the query (1–8, 9–64, 65–512 or over 512 positions). The difference is the prediction advantage. Pairs fall into six groups, by where the neighbour sits and whether its token is frequent (at least 20 occurrences among the analysed tokens) or rare. A group counts only if at least 200 of its pairs, and at least half of them, found a stand-in; the score is the plain average over the groups that count. (E2)

The rule for Stage B, written before any results. Each of the 32 candidate settings (memory 2, 8, 64 or whole × angle or lengths kept × the two averages × nearby tokens barred or not) is tested at each layer on four conditions: at least a quarter of its graph weight on other texts; not too much weight on nearby tokens; a neighbour list at most half the same as at no memory; and a list at most half the same as each text-only input's. A candidate passes if it meets all four at 5 or more of the 8 layers, in both models. Passing candidates are ranked by fewest interventions first (one average and nothing barred, then one average with nearby tokens barred, then each text's own average, then that with nearby tokens barred), then angle before lengths kept, then the smallest overlap with the text-only inputs, then the shorter memory. The prediction advantage could add at most one extra example. The rule picked lengths kept (dot) at memory 64, with one average removed and nothing barred. The owner set this pick aside and redesigned Stage B (see Deferred).

Controls

Three kinds of check sit beside the real texts. Automated tests compared each step with slow direct versions and hand-worked cases before any money was spent. Spliced texts, made by cutting two documents into alternating segments, test whether neighbours follow their source document beyond what position alone gives. Synthetic texts with a planted hidden structure show what a known structure looks like as neighbours.

Tests before any spending (exp1/test_census.py): the memory sum as streamed, against an explicit feature map and a direct double loop; the three bar rules against allowed sets written by hand; planted exact ties at the cutoff, including 64 taken from 1,024 tied candidates against a set tying all 1,024 (expected overlap 0.0625, largest 1); stand-ins never equal to the query, its neighbour or another neighbour, and replayable from their seeds; statistics, document resampling and the spliced-text baseline against hand values.

Spliced texts with expected answers: two pairs of documents, each pair from two different sources, cut into alternating segments of 384 to 640 tokens or of 48 to 80 tokens, giving 4 spliced texts. Each is analysed alone: its candidates are only its own tokens, and the one average of the 32 real texts is removed. The expectation: a token's neighbours should come from its own source more often than position alone explains, at little or no memory; at memory 64, less so for the short segments.

Synthetic texts with a planted hidden regime, a slow position drift or pure noise, run through the same census, so a known structure can be seen as neighbours. Only comparison by angle with one average removed was run on them (25 runs), not every combination of comparison and average.

Reference timescales

Two simple scales per layer, for reference beside the memory settings: how far back attention heads look, and how quickly hidden states change along a text. Neither measures how much context the model uses.

Per layer: how far back each attention head looks directly (its attention-weighted mean distance, leaving out attention to position 0; the median over heads), and the hidden-state half distance: the first lag at which the mean similarity (by angle) of two states of one text falls halfway from its lag-one value to the mean between texts. The half distance was measured at even layers only; odd layers were not measured, and every even layer reached halfway within 1,024 tokens. Neither is an effective context length. How to check there is nothing odd going on

An independent audit recomputes the results from the raw hidden states, with code that shares nothing with the pipeline. Its first report found a real bug: an integer overflow had zeroed the prediction overlap for neighbours and stand-ins in the later texts. The bug was fixed, the affected steps were re-run, and the audit then passed: 1,242 checks, 0 failed. The release uses the audited Stage A outputs, including the corrected prediction readout. The pilot (a separate local run) and the design settings are identified separately. You can also click any token in the viewer to see its neighbours, and a browser test checks the pages themselves.

An independent audit (exp1/audit_a.py: numpy only, importing nothing from the pipeline) takes 32 audit queries. For each, it recomputes the complete distance row from the raw hidden states by the explicit step-by-step sum, then the bar rules, the 64 neighbours with ties, the graph weights and the weight removed by barring nearby tokens. It replays the stand-ins from their seeds. It recomputes the census statistics from the stored lists for a sample of tokens, the prediction check from its stored per-document sums, and the rule for Stage B. It also compares 1,000 random pairs per pass with values the census saved before it discarded its distance blocks. The site does not build as a release unless this report is present and passing.

The audit has failed once, for a real reason. Its first report on these data failed one check, readout.document_contributions, in every model and settings group: the prediction check's stored per-document sums did not match the audit's own recomputation. The cause was an int32 overflow in the pipeline (exp1/readout.py, the lookup key of the prediction overlap), which recorded zero overlap for any neighbour or stand-in in texts 24 to 31 and the end of text 23; the small test case could not reach those indices. The fix uses 64-bit keys and adds two regression tests; the prediction check, the rule for Stage B and the viewer export were re-run, and the audit then passed. Prediction advantages rose; top-1 match rates, the share of pairs with a stand-in and the rule's pick did not change. The release uses the audited outputs, including the corrected prediction readout (E2).

Deferred

Several extensions were left out of Stage A; they are listed below. The Stage B planned when Stage A ran has been replaced. After seeing Stage A's results, the owner set the rule's pick aside and asked for a new design, described at the end of this section. That design has been written up and reviewed, but none of it has been run.

  • Keeping only each token's nearest neighbours in the graph, instead of weights on every token: on a synthetic graph this was measured to shift the result (SPEC.md), so the planned graph kept every link.
  • Model-derived lag weights; a recurrent random sketch; attention-weighted links across layers; a training-checkpoint axis; a width sweep; bars that grow with memory; mixing angle and lengths-kept comparison; longer contexts; more models.
  • The owner's later list: a sentence-embedding or vector-database baseline on the same texts, and the Hankel predictive-state construction of Golowich, Liu and Shetty.

Stage B as now designed (SPEC_B.md) uses independent chunks instead of long texts. Each of 2,048 Pile test documents not used in Stage A is cut once at a random position. The model reads the document up to the cut, and the chunk is the last 64 tokens up to and including the cut. No two chunks share a document, so the chains of neighbours along one text seen in Stage A cannot form. One average is removed, chunks are compared by angle (the lengths-kept "dot" setting is deferred), and nothing is barred. A chunk is summarised three ways: its state at the cut (the main one), its recent past at memory 8, and the average of its 64 states. The model's next-token prediction at the cut is built into the graph, and the main test asks whether cross-layer patterns pay a smaller prediction-disagreement penalty with the correct chunk-prediction pairing than with shuffled pairings. If run, it would add a "Through depth" tab and entries E4 to E6. Nothing of it has been run.
