What did this decide for the next stage?

Tested: {{fact:x.e3-selection.candidates}} candidate ways to build a memory-based similarity graph: memories 2, 8, 64, or the whole past; compared by angle (cosine) or by the distance between histories with vector lengths kept (the "dot" setting, where louder vectors count more); one average removed or each text's own average removed; nothing barred, or nearby tokens barred (tokens within 64 positions in the same text not allowed as neighbours). Evaluated on both models at all {{fact:x.e3-selection.sites}} measured layers. The tests use late queries: 2,048 tokens sampled from the last 512 positions of each text. They are compared with all 16,384 late candidates, the tokens in those last 512 positions of the {{fact:x.viewer.texts}} texts. This is the pool the old Stage B graph would have used. The selection rule was written before any results existed.

The rule written in advance picked {{fact:x.e3-selection.m}}. The project owner set that pick aside and redesigned Stage B instead. Out of {{fact:x.e3-selection.candidates}} candidates, {{fact:x.e3-selection.passing}} passed in both models, clearing all four tests together on at least {{fact:x.e3-selection.required}} of the {{fact:x.e3-selection.sites}} measured layers in each.

The four tests

The tests look at the graph the old Stage B would have built. In that graph each late query spreads a total graph weight of 1 over all late candidates, more to the more similar ones. The spread is tuned to be about as concentrated as an even split over 64 tokens. At each layer a candidate passes if: (1) at least a quarter of the graph weight goes to other texts; (2) not too much goes to nearby tokens (at most {{fact:x.e3-selection.m.near_mass_limit}} within 64 positions, or, when nearby tokens are barred, barring removes at most half); (3) memory changes the neighbours (at most half of the 64 nearest are the same as with no memory); and (4) at most half of the 64 nearest match those from either text-only input. Text-only inputs are vectors that know only which token is where: a fixed random vector per token id, or the model's input embeddings.

How the rule decided

The rule preferred candidates with no extra fixes (one average removed and nothing barred), then angle over lengths kept. No angle-based candidate passed without extra fixes. With angle comparison, memory 2 stayed too close to no memory; memory 8 passed on only {{fact:x.e3-selection.cand.cosine_c_8_none.m1.passing}} of {{fact:x.e3-selection.m1.name}}'s {{fact:x.e3-selection.sites}} layers; and longer memories put too much graph weight within 64 tokens. With lengths kept, two candidates passed without extra fixes, at memories 8 and 64. Memory 64 won because its neighbours overlapped less with the text-only inputs. Its worst overlap (the largest with either text-only input, at any layer, in either model) was {{fact:x.e3-selection.cand.dot_c_64_none.worst}}, against {{fact:x.e3-selection.cand.dot_c_8_none.worst}} for memory 8.

No second construction was added: there was no eligible passing alternative. The rule allowed one optional extra example, chosen by E2's prediction advantage. To be eligible, a passing alternative needed E2's completeness rule to hold at all {{fact:x.e3-selection.m.m1.layers}} E2 layers in both models (every non-empty group with enough stand-ins, and at least half of all pairs with one). None did. Had any been eligible, the one with the best advantage would have been added only if its resampling 5th percentile was above zero.

Why graph weight and the 64 nearest disagree

Graph weight does not go only to the 64 nearest tokens. In high-dimensional space, thousands of tokens are only moderately similar and sit at nearly equal distances. Each gets a sliver of weight, and together those slivers can outweigh the few close ones: about half or more of the weight ends up in other texts.

Averaged across all {{fact:x.e3-selection.sites}} measured layers for the rule's pick (M), {{fact:x.e3-selection.m.m1.screen_mass_other}} of graph weight in {{fact:x.e3-selection.m1.name}} lands in other texts ({{fact:x.e3-selection.m.m2.screen_mass_other}} in {{fact:x.e3-selection.m2.name}}). On those exact same late queries and late candidates, only {{fact:x.e3-selection.m.m1.screen_top_other}} of the 64 nearest tokens sit in other texts. For the same pick (lengths kept) over all {{fact:x.viewer.pool_tokens}} analysed tokens instead of the late pool, the share is {{fact:x.e3-selection.m.m1.census_other}}. Under angle comparison at the whole past, the split is even sharper: {{fact:x.e3-selection.flat.m1.walk_other}} of graph weight in {{fact:x.e3-selection.m1.name}} sits in other texts, versus {{fact:x.e3-selection.flat.m1.top_other}} of the 64 nearest on the same queries.

What happens next: a redesigned Stage B

After seeing Stage A's results, the project owner chose not to run Stage B on the rule's pick. The owner judged barring nearby tokens and removing each text's own average to be fixes for how the texts were sampled. The pick itself used neither fix; the owner changed what counts as a data point, from many positions per document to one independent chunk per document. He also asked for a construction that uses the model's prediction. For comparison, on E2's prediction advantage across the {{fact:x.e3-selection.m.m1.layers}} E2 layers, the pick (M) scores {{fact:x.e3-selection.m.m1.score}} versus {{fact:x.e3-selection.l.m1.score}} for the same lengths-kept setup with no memory (L) in {{fact:x.e3-selection.m1.name}}, and {{fact:x.e3-selection.m.m2.score}} versus {{fact:x.e3-selection.l.m2.score}} in {{fact:x.e3-selection.m2.name}}.

Stage B has been redesigned around independent text chunks—each the 64 tokens ending at a random cut in a different Pile test document—so nearby tokens from the same document cannot take over the graph. The new design removes one global average, compares by angle (cosine) with no tokens barred (deferring the lengths-kept setting), tests three summaries of each chunk (the state at the cut, the recent past at memory 8, and the average over the last 64 states), and builds the model's next-token prediction at the cut into the graph itself. This design is written and reviewed, not yet run, and neither the rule's pick nor the all-texts graph will be computed. Read the Stage B design (SPEC_B.md) →

Caveats

  • Passing limits graph weight, not the 64 nearest. At the pick's closest call (layer 10, {{fact:x.e3-selection.m1.name}}) {{fact:x.e3-selection.m.m1.layer10.near_mass}} of its graph weight was within 64 tokens, yet {{fact:x.e3-selection.m.m1.layer10.top_near}} of its 64 nearest late tokens were. Test 4 only bounds overlap with two text-only inputs. The rule tests geometry only: it does not use prediction agreement (E2) or later-stage patterns.
  • Test 1 never excluded the {{fact:x.e3-selection.cond1.cosine_c_none}} angle-based candidates with one average removed and nothing barred. Because graph weight spreads thinly across many moderately similar tokens, Test 1 held at every layer in both models for {{fact:x.e3-selection.cond1.cosine_c_none_full}} of those {{fact:x.e3-selection.cond1.cosine_c_none}} candidates.
  • Thresholds were fixed in advance. The limits in the table above were set before any runs, and the rule does not separate candidates far past a limit from ones right on it. The pick itself sat on a boundary: it passed in {{fact:x.e3-selection.m1.name}} on exactly {{fact:x.e3-selection.cand.dot_c_64_none.m1.passing}} of {{fact:x.e3-selection.sites}} layers, the minimum, with {{fact:x.e3-selection.m.m1.layer10.near_mass}} of its layer-10 graph weight within 64 tokens against the {{fact:x.e3-selection.m.near_mass_limit}} limit.
  • No candidate was skipped for budget reasons ({{fact:x.e3-selection.dropped}} dropped in this run).
