TransformerModes · Stage A

What do a language model's similar tokens have in common?

The long-term goal of this project is a map of what a language model does to a text, layer by layer. The plan is to connect the positions of tokens (a token is a word or piece of a word) whose internal states are similar, then find the main patterns of that graph. Whether such a map is useful depends on what "similar" ends up meaning. We wanted similarity to include each token's recent past, a setting we call memory. A small pilot suggested a catch: memory might simply make every token resemble its neighbours in the same text. The map would then say little more than "where am I in which document". Stage A (this site) checks that worry. It measures neighbours, graph weights and prediction agreement; it does not build the map. Stage B, the later stage that would build the map, is designed but not run. Decisions about the plan were made by the project's owner, Charles R-W.

We ran two 1-billion-parameter language models, {{fact:x.e1-neighbours.m1.name}} and {{fact:x.e1-neighbours.m2.name}}. Their tokenizers split these texts into identical tokens. Each model read the first {{fact:x.viewer.text_tokens}} tokens of {{fact:x.viewer.texts}} long documents from the Pile test set. The documents come from {{fact:x.method.probe.subsets}} sources, at most four per source. We analysed each token's hidden state after every second block (2, 4, …, 16). The main results use the state after block {{fact:x.e1-neighbours.m1.layer}} of 16 ("layer {{fact:x.e1-neighbours.m1.layer}}"). Nothing was trained.

How we counted neighbours

  1. Prepare each token's vector. At a chosen layer, subtract one average hidden state, taken over all {{fact:x.viewer.texts}} texts, so that what every token shares does not swamp the comparison. Then scale each vector to length 1, so loud and quiet tokens count equally (comparison by angle, or cosine).
  2. Compare two pasts end to end. To compare token t with token t′, line up their histories at the right end: t with t′, t−1 with t′−1, and so on going back. Add the step-by-step similarities, with weights that fade by a fixed factor per step. Memory sets how fast they fade, that is, how far back the comparison looks: none, about 2, about 8, about 64 tokens, or the whole past equally weighted. Then divide by the size of each weighted past, so the result is the cosine between the two weighted pasts. With no memory, only the two current vectors are compared; each already reflects earlier text, through attention. Because each step pairs matching lags, a token is never compared with its own position, so tokens t and t+1 are not similar just because their pasts overlap.
  3. Take the 64 most similar tokens. The first {{fact:x.viewer.burn_in}} tokens of each text are part of later tokens' histories, but are never selected as queries or neighbours. For each of the {{fact:x.viewer.pool_tokens}} remaining tokens, find the 64 most similar among all the others: from any text, earlier or later in the passage.
  4. Sort the 64 by where they sit. Each neighbour is in another text, in the same text more than 64 tokens away, or in the same text within 64 tokens (before or after). Average those shares over all analysed tokens. If the 64 were drawn at random, {{fact:x.e1-neighbours.m1.c.mem_none.chance_other}} would sit in other texts.

Three findings

Memory pulls neighbours into the same text, and right next door. Even with no memory, most of a token's 64 nearest tokens sit in its own text: {{fact:x.e1-neighbours.m1.c.mem_none.own}} in {{fact:x.e1-neighbours.m1.name}} and {{fact:x.e1-neighbours.m2.c.mem_none.own}} in {{fact:x.e1-neighbours.m2.name}} at layer {{fact:x.e1-neighbours.m1.layer}}, where chance would put {{fact:x.e1-neighbours.m1.c.mem_none.chance_other}} in other texts. Memory moves them right next door: in {{fact:x.e1-neighbours.m1.name}} the share within 64 tokens goes from {{fact:x.e1-neighbours.m1.c.mem_none.near}} with no memory to {{fact:x.e1-neighbours.m1.c.mem_64.near}} at memory 64. Now give each token a fixed random vector instead and run the same comparison. At memory 64 those vectors still keep {{fact:x.e1-neighbours.random.mem_64.own}} of neighbours in the same text, because texts reuse their vocabulary. But they put only {{fact:x.e1-neighbours.random.mem_64.near}} within 64 tokens, against the model's {{fact:x.e1-neighbours.m1.c.mem_64.near}}. At the whole past, random vectors already put {{fact:x.e1-neighbours.random.mem_whole.near}} within 64 tokens. E1: Where are a token's most similar tokens? →

Neighbours agree on what comes next, until memory grows. With no memory, a token's neighbours share its top next-token prediction about twice as often as stand-ins do: {{fact:x.e2-concordance.m1.c.mem_none.top1}} versus {{fact:x.e2-concordance.m1.c.mem_none.top1_control}} in {{fact:x.e2-concordance.m1.name}} at layer {{fact:x.e2-concordance.m1.layer}} ({{fact:x.e2-concordance.m2.name}}: {{fact:x.e2-concordance.m2.c.mem_none.top1}} versus {{fact:x.e2-concordance.m2.c.mem_none.top1_control}}). A stand-in is another occurrence of the neighbour's token in the neighbour's text, picked at random from tokens that are not neighbours. If neighbour and query share a text, the stand-in must also be in the same distance band from the query as the neighbour. The advantage shrinks as memory grows, to nearly nothing for the whole past. One limit: the comparison uses only pairs that found a stand-in, in groups where at least half the pairs (and at least 200) found one. That is {{fact:x.e2-concordance.m1.c.mem_none.used}} of all pairs with no memory, and {{fact:x.e2-concordance.m1.c.mem_whole.used}} for the whole past. A rule written in advance picked a setup; the owner then redesigned Stage B. A rule written before any results existed was applied to {{fact:x.e3-selection.candidates}} ways of building the similarity graph. It had four tests: enough of the graph's link weight goes to other texts; not too much goes to nearby tokens; memory changes the neighbours; and the neighbours differ from what the tokens alone give. It picked {{fact:x.e3-selection.m}}. The "dot" setting measures the distance between histories with vector lengths kept, so louder vectors count more. "Barred" tokens are not allowed as neighbours; "nothing barred" means every analysed token may be one. After seeing Stage A's findings, the owner set that pick aside. Stage B was redesigned around independent text chunks, one per document, compared by angle with nothing barred. The new Stage B is designed, not yet run.
