**I would allow the calibration after one seed correction.** The design is defensible as a test of the **selected fixture**, but §9 overstates the case when it says calibration “cannot make K1–K5 easier.”

- **Separate the random streams before calibration.** Development sequences use seeds 170–174, but confirmatory distractors and noise use `seed + 100`, i.e. **170–172** (§9, lines 282–283, 301). The draws are transformed differently, but they start from the same RNG states. Keep confirmatory seeds 70–72 unchanged and move the development seeds to a verified unused range, or use distinct phase-and-role namespaces. The shared fixed loadings and scramble are intentional; this overlap is not.
- **Describe what selection does.** Increasing \(v_g\) reduces the belief’s fraction of raw variance. It does **not** monotonically reduce product gain: cosine normalisation, adaptive graph weights, and both the observed and wrong-pairing eigenspaces change. A stronger distractor could also make a negative-control ceiling easier to meet. The safeguard is **not** that the grid moves in a proven conservative direction. It is that only K0 quantities select the first qualifying value, the selection rule is frozen, and K1–K5 are tested once on fresh records. Report a pass as conditional on that calibrated fixture, not as evidence of robustness across distractor strengths.

**The parameter table is sufficient to define the statistical fixture.** For exact replay, pin the generator code as well: the current implementation draws initial states in a batch, then makes one batched inverse-CDF transition draw and one emission draw per time step. Before development, freeze that code, the grid and stopping rule; reuse identical underlying draws at every grid point, changing only the scaling of \(g\).
