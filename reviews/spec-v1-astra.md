**Verdict: revise before funding the full run.** The end-aligned kernel is faithful to the owner’s definition, and the through-depth eigensolver is a defensible choice. The main problems are in how the spec proposes to *recognise success*. One hard gate rejects a correct pipeline on noise. Conversely, the winner rule can give a perfect score to a picture determined entirely by token formatting. Neither problem requires a large experiment to demonstrate.

### Blocking before the full run

**1. The noise control tests the wrong null, and is likely to stop the experiment.** §7.2, lines 234–240; §9.1, lines 298–326; §11, lines 373–377.

Pooled A and B reuse the **same realised noise vectors** on every shared token. Their rows against other shared tokens also reuse exactly the same distances. A graph can therefore reproducibly organise noise without recovering an independently drawn regime or any property of a model. Permuting token labels in one finished picture destroys this agreement; it is not the null for resampling the same point cloud.

I checked this with the actual sibling participation-ratio kernel and joint solver: four contexts, four sites, isotropic width-64 Gaussian noise, no memory, 256 nodes per graph, half shared, \(k=64\), 16 modes. For three seeds, A/B alignment was **0.514, 0.561, 0.578**; the corresponding within-document permutation 95th percentiles were **0.138, 0.137, 0.135**. This is a small demonstration, not a forecast of the production values. It is enough to disprove K4 as a known answer and to show why an absolute stability gate of 0.5 is not evidence of meaningful structure.

**Change:** separate three questions. Use independently redrawn noise fields on the same indices for a no-cross-replication control; use the *same* noise field for an overlap-matched baseline for A/B stability; test recovery of independent regime labels against independent **Markov labels with the same persistence**, not shuffled individual tokens. Do not stop on an expected same-cloud stability signal. Run the controls with the graph rule actually selected: P2 and U5 currently run concurrently before that rule is known.

**2. The winner rule can select a wholly obvious, non-model-specific construction.** §1, lines 20–24; §§7.2–8, lines 234–291; E2, line 474.

The remainder means “outside these particular additive columns,” not “beyond token identity, position and document.” It retains previous-token identity, recent punctuation or indentation patterns, rare tokens, document-by-position interactions, and position oscillations faster than 224 tokens. Memory explicitly supplies recent token history to both models. For an exact counterexample, take a shared formatting function outside \(Z\), residualise it against \(Z\), and let both pictures concentrate on it. Remainder share, resampling stability and cross-model agreement can all be 1. The score need not even represent broad agreement: Hilbert–Schmidt alignment squares the strengths of the directions, so one strong shared direction can dominate many unrelated ones. Meanwhile the reproducibility gate is on **raw** \(R\), not on the remainder that wins the contest. Finally, line 285 ships a winner even if every candidate fails.

**Change:** run a cheap text-only adversary on exactly these tokens, e.g. fixed token-type vectors passed through the same memory filter, with a prespecified formatting/position baseline. Test whether it can reproduce the claimed winning picture. Gate on reproducibility of the **remainder**, report its retained energy and effective rank, and report a paired comparison with the same-reading no-memory baseline. Define an explicit **“no supported winner”** outcome; a browseable reference default is fine, but is not a scientific winner. A fixed-graph document bootstrap is conditional on these graphs, not a refit or independent confirmation of the winner among eight. Label it that way. If interpretability *utility* is claimed, add one independent readout, for example whether graph neighbours share next-token predictions beyond text-matched controls. Otherwise call the score what it is: shared descriptive geometry.

**3. A/B agreement is not a ceiling, and Q3 cannot establish that a single text is an unbiased sample.** §3, lines 87–98; §5, lines 172–177; §7.4, lines 265–273; E3, line 475.

A and B have equal size, half-overlapping nodes and the same 32 documents. The single graph has seven times as many nodes from the evaluated text as pooled A and no other texts. A fixed 64 neighbours does not fix a geometric radius or the fraction of a text seen by a row. In particular, the single graph uses *all* the shared positions and the rest of that text; it can agree with A **more** than B does. The reverse can occur solely because pooled modes distinguish documents: after restricting to one document and centring, almost none of their signal remains. Normalised alignment of that residue can still return a number. Sinkhorn gives a uniform stationary distribution on each finite graph; it does not make these two sampling designs equivalent.

**Change:** retain Q3 as the useful descriptive comparison the owner asked for, rename A/B a **pooled-resampling reference**, and show how much centred signal survives restriction before scoring it. Add one matched thinning comparison on a few prespecified texts to distinguish thinning from adding other documents; match or report the realised neighbourhood radius. Say explicitly that generalisation to an unseen text awaits the deferred leave-one-document-out experiment. No Nyström implementation is needed to correct the present interpretation.

**4. The $47 estimate does not yet justify an $80 ceiling.** §4, lines 158–165; §11, lines 361–385; §16, lines 554–557.

The Gram arithmetic is off in the *conservative* direction: \(2(528)(2047^2)(2048)=9.06\times10^{12}\) FLOPs **per site**, about \(7.25\times10^{13}\) over eight sites. The important omission is the cost outside that multiply. In `/home/ubuntu/code/DepthEmbedding/invert/dm.py:107–160`, `_cond_rows` performs 50 full-array bisection evaluations after bracketing, with multiple exponentials and temporaries per evaluation. Much of that NumPy path is not a 16-core BLAS operation. Then come Sinkhorn, site eigendecompositions, balancing, and the joint solve.

I timed **only `_cond_rows`** at \(N=384,768\): 0.50 s and 2.44 s on this VPS. A simple \(N^2\) extrapolation gives **5.7–7.1 minutes for U4’s 32 row builds**, against 4.5 minutes for its entire unit; **60–74 minutes for U3’s 16 row builds**, against 70 minutes for its entire unit. These are not Modal benchmarks, but they show the estimate has no demonstrated margin. The sibling `/home/ubuntu/code/DepthEmbedding/opt/REPORT.md:16–23,64–67` concerns a different kernel or component and explicitly disclaims a full large dense Gaussian benchmark. Shrinking pooled \(N\) will not fix U4; nor does it proportionately reduce the all-prefix Gram work. Splitting U3 by memory also invites recomputing the same Gram four times.

**Change:** make the first paid step after the corrected cheap controls a **capped end-to-end timing pilot** for one representative single unit and one pooled unit, with stage timings, peak RSS, measured billing and an explicit stop if *total* projected spend exceeds budget. Reuse a Gram block across memories, stream blocks, derive site scales from the full site eigensystem already computed, and parallelise or chunk row calibration explicitly. Make the fallback regenerate node counts, references, thresholds and page labels rather than merely changing \(N\). Clarify the dependency of `decide` on readings currently assigned to the later U7.

### Should fix before interpreting results

**5. The primer’s noise claim is false; whole-prefix dot versus cosine does not isolate loud tokens.** §1, lines 22–23; §4, lines 120–155; §9.1 K5, line 323.

Even with independent, zero-mean token vectors, two consecutive Gram entries *along a diagonal* reuse their history: \(K_{i+1,j+1}=G_{i+1,j+1}+aK_{ij}\). For two independent white-noise documents at steady state, the correlation between those successive entries is \(a\), not zero. That does not mean every adjacent pair of tokens is similar; it means a chance match persists at shifted endpoints even without token autocorrelation. For whole-prefix, independent unit vectors in dimension \(d\) give cross-document cosine variance \(1/[d\max(t,t')]\): the **distribution** depends on position even when the mean is zero. Moreover, even when *every token has exactly unit norm*, the whole-prefix dot distance is \((t+t')/2-\sqrt{tt'}\,\hat c\), not \(1-\hat c\). The two readings can diverge with no loud tokens at all.

**Change:** distinguish expected similarity from dependence among graph entries. Include a flat-norm white-noise, position-stratified distance/neighbour check. For Q2 add a small diagnostic that fixes token normalisation and varies just prefix normalisation, or report length-matched pairs. Without that, describe Q2 as a comparison of **two combined geometry choices**, not an attribution to loud tokens. Also remove “any lag profile at no extra cost” at line 150: the one-step recursion is special to geometric weights.

**6. The planted and stitched targets mix actual invariants with empirical predictions; one stitch control can pass on position alone.** §9.1–9.2, lines 302–336; E1, line 473.

For S512 I projected the centred A/B label, on exactly positions 256–2047, onto the spec’s 16 position harmonics. **91.4%** of its energy is captured, comfortably above the 0.5 success threshold, without reading a token. S64 has a different problem: periodic alternation does not necessarily disappear with long end-aligned memory. If residuals encode a clean alternating A/B square wave, endpoints one full period apart match at *every aligned lag*; endpoints half a period apart disagree. Longer memory can sharpen phase rather than erase it. The two schedules also use different source documents. On the synthetic side, an undetectable *pairwise* cosine difference need not be undetectable by a graph aggregating thousands of pairs (K1), and coupling can carry a regime into site 0 even if that site's inputs contain none (K2). The sibling operator is designed to do exactly that. Changing amplitudes on seed 0 does not make these numerical thresholds mathematical invariants.

**Change:** distinguish hard implementation checks from power and leakage measurements. For K2 show site-only versus coupled recovery at the absent site. For stitches reuse the same source pair across schedules, randomise segment lengths or phase in matched replicates, and compare against a position-only baseline; report rather than prescribe the direction at whole-prefix. The existing text already says the stitches are not a gate; make the E1 sentence equally conditional. A small exact positive control plus a valid noise negative is more useful than five fragile hard targets.

**7. The cutoff and token-space summaries have two material spectral errors.** §6, lines 214–218; §7, lines 225–230, 244–264; §13, lines 511–515.

A small **16/17** gap means the **16-dimensional space itself** may be unstable. It is an internal tie, with a separated outer boundary, for which the space remains reliable while individual modes do not. Rotation invariance within the retained 16 does not cure rotation *across* the cutoff. Also \(R\) combines repeated directions but does not count each once in weight: four orthogonal depth envelopes of the same token function give \(R=4uu^\top\). The sibling test explicitly checks this in `/home/ubuntu/code/DepthEmbedding/test_spacetime.py:163–179`. Taking an unweighted top 16 of \(R\) can therefore pad the captured-share statistic with arbitrary near-zero directions.

Two exact checks also need correction: since each slice is mean-zero, the constant contributes **zero** chance share; the document chance dimension is 31 pooled and 0 single, not 32 and 1. A raw position harmonic on randomly sampled pooled nodes generally has nonzero document means, so the proposed exact `(0,1,0,0)` test is not true there.

**Change:** check the joint cutoff and the recurrent-spectrum cutoff separately; compare nearby retained ranks or keep a separated band when either is weak. Use a declared numerical/effective rank for unweighted captured share, or a strength-weighted readout with a matched reference. Use centred nuisance ranks, and test an explicitly document-residualised harmonic. In the primer also correct \(t^*\): it equates two **eigenvalues**, not the within- and between-layer energy terms. `/home/ubuntu/code/DepthEmbedding/SPEC_SPACETIME.md:92–99` makes that distinction explicit.

**8. The graph-rule pilot does not test the failure it cites in the product it ships.** §5, lines 179–198; §11, lines 365–377; E4, line 476.

The prior result is real, but `/home/ubuntu/code/DepthEmbedding/invert/NOTES.md:37–50` reports **joint** modes, two-image mass and Shannon perplexity 400. This pilot counts **single-site** modes with participation spread below 20, mostly in single-text cells, using different effective widths. For instance, a mode placing 10% of its mass on two points and spreading the rest uniformly need not have spread below 20. The 1% tie margin tolerates about 51 extra localised modes; all 16 visible modes could be bad in a particular pooled configuration without changing the winner. None of the production gates then checks that viewer’s joint modes for localisation.

**Change:** retain the inexpensive site screen but check the actual first 16 **joint** modes of finalists on a pooled and a single example, measuring worst two-token mass and spread, including depth-aggregated token mass. Report pooled and single results separately. If widths are not matched, conclude about these three *configured recipes*, not about Shannon versus participation ratio in general. The \(1/\sqrt{k}\) bound itself is correct for the pre-Sinkhorn conditional, not guaranteed for the final walk.

**9. The independent checker and the click-to-verify promise cannot be implemented from the specified outputs.** §11, lines 379–386; §12.1–12.2, lines 416–421, 438–450; §12.5, lines 485–499.

Only `/analysis` and `/site` are fetched. The latter contains two choices, pooled A, and int8 display slices—not the full-precision inputs, B, synthetic labels and all eight candidates needed to reproduce the decision at \(10^{-6}\). Rechecking the already chosen construction is not an independent check of the argmax. Uniformly sampling 200 pairs from a pooled graph gives only **0.24 expected matches** among the stored ten neighbours per row. Sampling *from* the stored neighbour list instead verifies values, but cannot detect a closer omitted neighbour.

The reader also sees pre-graph nearest tokens, not the edges that actually drive the mode after adaptive widths and Sinkhorn. The last 24 tokens shown cover only **31.5%** of the geometric weight at \(m=64\), and **1.2%** of a whole prefix at \(t=2047\). They illustrate the comparison; they do not show “what it compared” in full. Per-node same-document walk mass is promised on click, but only the site average is listed in storage.

**Change:** run the independent checker beside the raw arrays or export a separate audit bundle. Recompute **all** decision inputs and the ranking; sample query rows, independently recompute distances to **all** eligible nodes for those rows, and verify neighbour membership as well as values. On the page, one expandable worked token is enough: show raw nearest versus largest final walk weights, the fraction of memory displayed, and one check of the local eigen-equation. Verify dot-distance values are representable before casting to float16. This provides more auditability than another scatter plot.

**10. The visible mode numbers invite a comparison the analysis deliberately avoids.** §12.1, lines 397–435; §12.3, lines 452–463.

“Mode 3” of one graph, memory or model is not “mode 3” of another. Its sign can reverse and its direction can exchange with a neighbour. Toggling the model or graph while keeping the same button selected can visually suggest a scientific difference even when the two low spaces agree exactly. The arbitrary-sign note does not explain exchanges. Also the stitched contexts have no pooled nodes, so one of the advertised graph choices is undefined there.

**Change:** keep the text, depth bar and clicked-token example in the main view. On a change of construction say “mode numbers are local to this graph”; show an invariant shared-token agreement or a clearly labelled post-hoc matched direction if a visual comparison is offered. Disable pooled for stitched texts. Put scatter, detailed indices and robustness plots behind one disclosure. This is both simpler and more faithful to the owner’s request for few views.

**11. Q5 measures two descriptions, not how far a model uses context; the causal check also overstates its precision.** §2, lines 52–57; §§9.3–10, lines 338–352; E5, line 477.

Attention distance is conditional direct attention mass, not influence through values, heads, MLPs or earlier layers. Residual cosine can persist through shared vocabulary or topic; the first half-crossing may not exist, may be driven by a single lag, and zero is not necessarily the within-document background. Thus “64 is beyond the models’ own range” is not supported. Separately, I checked the pinned Transformers 4.57.6 source: **both** eager attention implementations explicitly compute softmax in float32; OLMo also explicitly casts to float32 in layer norm, and both use float32 rotary arithmetic. `.double()` alone is not an all-float64 forward oracle with guaranteed \(10^{-10}\) shape-to-shape agreement. This does not prove the tolerance will fail, only that it is not justified as stated.

**Change:** label E5 “direct attention distance and residual autocorrelation,” report the background and censored/no-crossing cases, and do not interpret either as effective context length. For causality, compare two **equal-shape** inputs identical through the cut but with different suffixes; also check that changing the current token can change its own recorded state. Keep the truncated mixed-precision run as a numerical diagnostic, or implement and validate a genuine double-precision reference before making that tolerance a hard gate.

**12. Publicly serving 34 long text excerpts needs a separate publication gate.** §3, lines 61–77, 103–108; §12, lines 388–405, 440–448.

The pinned dataset card says `license: other`. Its stated cleaning procedure removes five source subsets based on whether use for **training** is permitted. That is not evidence that every remaining article, code file or post can be republished verbatim on GitHub Pages. Filtering three literal PII placeholders also does not filter ordinary email addresses or other personal data. This matters here because the proposed public deliverable includes the text itself, not just statistics.

**Change:** choose auditable sources with suitable redistribution terms and preserve attribution; screen viewer excerpts for personal data before deployment. If the scientific probe must stay as designed, use separately cleared, prespecified display examples and keep full-text audit inputs off the public site. Do not silently describe a capped, ASCII-heavy sample of long document beginnings as random natural text in general.

### What I would retain

- The feature-map derivation and diagonal recurrence in §4 are correct; a running mean of vectors is **not** an equivalent shortcut. Using the same centring vector across node sets is a good way to isolate the effect of changing the graph, provided “single text” is labelled as using a corpus mean.
- The pinned configurations confirm the different end-of-text IDs, matching model widths and context limits. The ordinary BPE merge lists match. Keeping the per-document ID assertion is preferable to trusting that metadata.
- The sibling code supports the mean-zero sector, relative site scales, direct balance calculation and residual check. The alignment formula is correct for nonzero PSD pictures and reduces to mean squared principal-angle cosine for equal-weight projectors. Use centred factors after restriction and define what happens when their norm is negligible.
- Reuse the graph code, but test its **interface**: `/home/ubuntu/code/DepthEmbedding/invert/dm.py:147–155,178–183` expects a similarity-like input and internally computes `1-C`. Pass `1-d` for the dot-distance recipe, not `d` or the raw dot Gram. The old dot convention also divides by mean squared norm; that overall scale is immaterial to ideal adaptive rows and neighbour ranks, but not to reported distances or the absolute duplicate check.
- The minimum useful first experiment is smaller than the planned one: valid noise and planted controls, one text-only baseline, one end-to-end cost pilot, then the fixed memory comparison with a no-winner option. Defer the wide graph-rule sweep and coupling robustness runs before sacrificing any of these checks.
